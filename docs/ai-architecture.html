AI architecture of Lịch AI20K

Two model calls, and code around both. The schedule, map, reminders and sign-in never touch a model. A model is called only to draft a leave-request email and to summarise what is left of the week. Code decides what goes in, and checks what comes out.

Leave request: who decides what

This is the slice the judges evaluate. A model is good at wording a formal Vietnamese email and at judging whether a reason is complete. Everything that has one right answer stays in code.

Before the call · codeStops early when it can

  • Refuses requests to invent evidence, send automatically or change the recipient
  • Asks for the student ID if it is missing, or says it is not in the timetable
  • Refuses a date that is a holiday
  • Finds the session from "LEC 15", "27/11", "chiều thứ 6"; asks which one if 0 or more than 2 match
  • Asks for a clearer reason if it is under 8 characters

Most bad inputs never reach the model.

The call · modelJudges and writes

  • Gets only the facts: ID, class, reason, evidence type, the matched session's name, date, time and room
  • Decides ready, ask back (one question) or refuse
  • Asks for evidence when the reason is medical and none is listed
  • Drafts the subject and a short formal email under 150 words
  • Treats the student's reason as data, never as instructions

One call per request.

After the call · codeChecks before showing

  • Status must be one of the three; anything else is rejected
  • Every date, time and room code in the draft must appear in the facts
  • Recipient comes from LEAVE_RECIPIENT, never from the model
  • Builds an Outlook compose link and copy buttons; nothing is sent by the app
  • The student can edit the draft and attaches evidence in Outlook

The human always presses Send.
